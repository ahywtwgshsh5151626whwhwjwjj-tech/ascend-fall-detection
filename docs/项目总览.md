# 昇腾派社区康复跌倒检测项目

## 交付包说明

本目录是从 Orange Pi AIpro 20T（Ascend 310B1）昇腾派导出的项目交接包，包含正式可运行源码、正式模型、采集数据、关键点数据、评估报告、实验版本和部署说明。

本包保留了完整源码快照，同时将常用内容按用途分类。正式运行入口和正式模型已经单独标明，实验模型和候选代码不能直接替换正式版本。

## 当前正式版本

- 正式入口：`01_正式代码/完整可运行源码/main_pose_safe.py`
- 正式启动脚本：`01_正式代码/完整可运行源码/start.sh`
- 正式目标检测模型：`02_正式模型/目标检测模型/yolov8n_pose.om`
- 正式时序模型：`02_正式模型/时序分类模型/real/tcn_fall.npz`
- 正式状态机和检测器：`01_正式代码/完整可运行源码/fall_ai/fall_engine.py`、`pose_fall_detector.py`
- 默认启动模式：静音启动，`REHAB_SILENT=1`

## 项目技术链路

```text
USB 摄像头
  -> OpenCV/V4L2 取帧
  -> YOLOv8 Pose .om（Ascend 310B1/NPU）
  -> COCO-17 人体关键点
  -> NMS + IoU 轨迹关联
  -> 姿态角度、髋部高度、下坠量等规则特征
  -> 54 维关键点时序特征
  -> Numpy TCN 时序分类器
  -> 规则分 + TCN 分融合
  -> 连续确认状态机
  -> AlarmManager 音频告警、截图和 hard-negative 回流
```

## 已知工程边界

- 摄像头画面中人物必须尽量完整，头部、肩部、髋部和主要腿部不能出框。
- 多人、旁人遮挡和背景重复框会降低检测稳定性；正式版本保留多人/边缘保护逻辑。
- 非跌倒动作不会播报，只有进入最终跌倒确认状态才会播放音频。
- 告警按回车确认或空格取消后，必须等待人员重新站立并回到 `NORMAL / IDLE`，系统才会重新武装。
- 当前实验版本的误报/漏报回归结果保存在 `04_评估报告`，不要仅凭单段视频决定替换正式模型。

## 交接原则

正式运行只使用 `01_正式代码` 和 `02_正式模型` 中标记的文件。`05_实验版本与备份` 仅用于分析、复现和后续开发。
