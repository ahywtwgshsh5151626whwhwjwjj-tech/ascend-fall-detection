# Ascend Edge Vision Demo

基于国产昇腾 310B NPU 的边缘侧跌倒检测演示系统，面向社区康复、养老照护与本地化安全感知场景，支持实时摄像头与本地视频双路检测，全程离线运行，不依赖云端服务。

---

## 🎯 项目定位

本项目不是一个泛化的"姿态识别 Demo"，而是一个面向社区康复 / 养老场景的边缘 AI 功能模块原型。

它尝试回答这样一个问题：

> 在国产信创硬件上，是否可以用纯本地、可解释、低成本的方式，实现"跌倒检测 + 本地告警 + 事件留痕"的完整闭环？

选择"跌倒检测"作为切入口，而不是一步到位做完整康复系统，原因很明确：跌倒属于高价值安全事件，业务意义清晰，场景容易理解，规则可解释，适合边缘设备部署，便于后续向康复动作分析、行为量化逐步扩展。

---

## ✅ 当前已实现能力

当前版本为 **v1.0.0 稳定演示版**，具备完整的检测 + 告警 + 留痕闭环：

- 实时摄像头人体检测与框选
- 本地视频文件人体检测与框选

- 实时 FPS 显示（画面左侧叠加，滑动平均平滑）
- 桌面快捷方式启动支持（.desktop + start.sh，双击即启动）


目前项目已可作为一个可运行、可演示、可讲解的工程原型。

## 🧩 场景价值

适合以下场景：社区康复驿站、养老活动区、本地值守安全监测点、对隐私敏感或要求视频不出域的场所。

其核心价值不在于"多聪明"，而在于：

- 视频留在本地，结果可结构化输出
- 不依赖公网，不依赖外部 API
- 可作为平台中的边缘感知模块嵌入现有系统
- 可作为社区 / 街道 / 康养项目中的演示型能力模块

▶️ 快速运行
1. 准备模型
将已转换好的 yolov8n_pose.om 放入项目根目录。
2. 安装依赖
pip install numpy opencv-python
sudo apt install fonts-wqy-zenhei
3. 运行
python3 main.py
注意：需要在有图形界面的环境下运行（本地显示器或 X11 转发），Tkinter 不支持纯 SSH 终端启动。

💡 边缘部署踩坑记录
模型转换：Ultralytics 默认导出 ONNX 为较高 opset，当前工具链不一定兼容，需按设备环境重新导出并转换。
ACL 资源初始化顺序：ACL 初始化、模型加载、输入输出缓冲区申请顺序必须严格控制，顺序错误会导致推理链路静默失败。
OpenCV 类型兼容：在 ARM / 昇腾环境下，部分 OpenCV 绘图接口对 numpy 数值类型非常敏感，需要绕开默认接口。
坐标映射：推理空间为 640×640，显示空间为 640×480，x/y 方向需分别缩放，否则框体错位或覆盖整个画面。
时间连续性：跌倒检测本质是时间序列任务，线程切割不当会导致状态机历史断裂，出现"有人体检测但无跌倒报警"的问题。
不可见字符污染：从聊天窗口复制代码时可能混入 U+200B 等不可见字符，为此额外编写了 clean_tool.py 进行清理。
双路推理帧率瓶颈：NPU 串行执行两路推理时帧率减半（双路约 5~6 FPS），采用分时复用方案（每帧交替推理摄像头与视频），可将单路有效帧率提升至 10~13 FPS，是 310B 在当前模型下的实测上限。
桌面启动环境变量缺失：通过 .desktop 文件启动程序时，CANN 环境变量（set_env.sh）和 DISPLAY 变量均不会自动继承，需在 start.sh 中显式 source 和 export，否则程序静默失败，无任何报错提示。
